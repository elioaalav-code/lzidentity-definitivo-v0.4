[ 02 ] UNIFIED IDENTITY · EVM → NOSTR

One signature,
two networks.

Nostr can't verify Ethereum signatures directly — different signing scheme. So we derive: you sign one deterministic message with your EVM wallet, we hash it, and a Nostr key falls out. Same wallet, same key, forever.

Connect a wallet, then click "Sign & derive" to generate your Nostr key.
1

Connect your EVM wallet. MetaMask, Rabby, Frame — anything that exposes window.ethereum works.

2

Sign one message. You'll see a personal_sign prompt with a fixed string. Your wallet returns a deterministic 65-byte signature.

3

Hash to seed a Nostr key. We sha256 the signature → 32 bytes → a valid secp256k1 private key → Schnorr x-only pubkey → bech32 npub.

4

Same wallet, same npub. Always. Switch device, reconnect — the derivation is deterministic. Your Nostr identity is the cryptographic shadow of your EVM identity.

[ 04 ] TRANSPORTS · THREE LAYERS, ONE INBOX

Three ways out.
Always one in.

Each transport optimizes for a different physics. CipherMesh picks the right one per message — or you override it from a long-press.

[ ble mesh · offline ]

Mesh

Bluetooth mesh for venue floors, festivals, and any place the cell tower can't help. Hops through nearby peers, no internet required.

range~80m per hop
latency120–400 ms
cipherx25519 + chacha20
[ nostr · relayed ]

Nostr

NIP-44 gift-wrap over a chosen relay set. Messages are encrypted, signature-bound, and stored long enough for a peer to come back online.

relays4 default · user pick
formatNIP-44 + NIP-59
identityderived from EVM
[ layerzero v2 · cross-chain ]

LayerZero

Encrypted payloads ride OFTv2 messages between chains. The DVN verifies, the executor delivers, your message lands with a signed receipt on both sides.

routesETH ⇄ ARB ⇄ OP
finality14–90 s · DVN-quorum
fee~ $0.02 / message
