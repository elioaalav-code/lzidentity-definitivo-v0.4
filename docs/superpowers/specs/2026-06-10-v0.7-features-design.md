## F1 — Passkey keystore (the site's own TODO: the DEMO MODE card)
Today: `cm:priv` plaintext in localStorage (shared.js LS.PRIV; restore() reads it).
New module `assets/js/keystore.js` (window.LZ.keys + ESM exports):
- `status()` → `unprotected | locked | unlocked | none`
- `protectWithPasskey()` — WebAuthn PRF: create credential w/ `extensions.prf`,
  derive 32-byte secret via get()+prf.eval{first:salt} → HKDF → AES-GCM-256
  encrypt priv. Store `cm:keystore` JSON {v:1, kind:"prf", credId, prfSalt, iv, ct}.
  DELETE `cm:priv`.
- `protectWithPassphrase(pw)` — fallback when PRF unsupported: scrypt
  (@noble/hashes via esm.sh, N=2^17 r=8 p=1 — NIP-49 params) → AES-GCM.
  {v:1, kind:"pw", salt, iv, ct}. (Marketed as "passphrase encryption", not
  NIP-49-compliant container.)
- `unlock()` — modal (LZUI.modal): Touch ID button or passphrase field →
  decrypt → set `state.derived.priv` IN MEMORY ONLY → dispatch
  `window "lz:keys-unlocked"` → callers re-render. `lock()` clears priv.
- shared.js changes: derive() → if keystore exists, re-encrypt new priv (or
  prompt protect); restore() → when `cm:keystore` present: state.derived =
  {addr, npub, priv:null}, `state.keyLocked=true`. Existing plaintext cm:priv
  (legacy) keeps working = "unprotected" status with upgrade CTA.
- Consumers keep reading `state.derived.priv` — zero signature changes. Gates
  that today mean "underived" must distinguish LOCKED: chat renderList/Thread,
  communities composer → "Unlock" CTA (calls LZ.keys.unlock) instead of derive
  CTA when status==locked. chat-nostr listens for lz:keys-unlocked → init().
- Identity: the static DEMO MODE `.id-row` becomes a dynamic protection card
  (#idProtection): unprotected → warn copy + "Protect with passkey" button;
  prf/pw → green "Protected by passkey/passphrase" + Lock now; locked → Unlock.
- Verify: headless via CDP virtual authenticator (WebAuthn.enable +
  addVirtualAuthenticator ctap2/internal, hasUserVerification, hmac-secret for
  PRF). If headless PRF unsupported → verify passphrase path headless + PRF
  manually (documented honestly in report).

## F3 — Identity Link (npub↔EVM attestation) + pay-by-contact
- Attestation: Nostr kind **30078** (NIP-78 app data, parameterized replaceable),
  tags [["d","lz:idlink"]]. content = JSON {v:1, addr, msg, sig}:
  msg = `LZidentity link v1: ${npub} <-> ${lowercase addr}`;
  sig = EIP-191 personal_sign(msg) from that addr (eth_sign path via
  eth.request personal_sign — the same provider already used).
- Publish: Identity view card "Identity Link" (#idLink): after derive+wallet,
  button → personal_sign → publish via pool. Shows linked/unlinked status.
- Verify (`verifyIdLink(evt, expectedNostrPub)`): parse content; recompute
  EIP-191 digest keccak256("\x19Ethereum Signed Message:\n"+len+msg) with the
  EVENT author's npub in msg; secp256k1 recover (@noble/curves, keccak from
  @noble/hashes/sha3 — same esm.sh family as hyperliquid.js) → address ==
  content.addr. Nostr layer already authenticates evt.pubkey.
- Chat: opening a conversation fetches kinds:[30078] authors:[pub] "#d":
  ["lz:idlink"] limit 1 → on verified: thread-head chip `✓ 0x1a2b…9f` +
  **Send** button → #/wallet with quick-send TO prefilled (resolve the real
  input IDs at impl time) + toast. Cache per-pub in module state.
- Quick send: TO accepts npub (placeholder already promises it!): on npub input
  → resolve via the same attestation lookup; unverified npub → honest error
  "This npub has not linked an address".
